Stage 5 notes:
- **Two formats, one importer:** `TOOL.id=['beam','beam-builder']` (template list support, no template change needed), `major:0`. `plan` / `apply` get the matched tag; untagged recipes are told apart by structure (`topology.name` -> Library, `beams[]` + `cell.name` -> Builder). `apply` writes state without rebuilding (topology, radius, cell, material, `Builder.loadBeams`, name, radius) and ends with one `switchTab(mode)`, which is the single rebuild and solve (Library: `setParams` + `updateMetrics`, Builder: `Builder.refresh`).
- **Material:** E_s / nu_s from `homogenization.material` are written to `materialEs` / `materialNu` and the number inputs directly. `onMatChange` is not used: it turns nu = 0 into 0.34 (`parseFloat(...) || 0.34`, an existing bug that is left alone).
- **Custom cells:** `bldPushToLibrary` was split into `registerCustomCell(key, name, beams)` (idempotent, also updates the dropdown option). A Library recipe whose topology is not in the catalog but carries beams registers a cell under the exact key (key must match `[A-Za-z0-9_.-]{1,64}`, <= 256 beams, coords clamped). A key already registered this session takes the recipe's beams (warning), so round trips are exact.
- **Undo:** `exportRecipe` returns the active mode's export plus an in-memory `__snap` with both modes' inputs (never exported), so Undo restores the mode, the Library state and the previous Builder beams (history stack is not restored).
- **Recipe menu:** Open recipe…, Export JSON, Export LTCX, Export CSV, Queue, Choose queue…, Mesh, Lab. `CONFIG.recipe.exportBtn` is a function (active mode's native button); `extra` adds LTCX / CSV, each clicking the native button so behaviour and filenames are unchanged; header message says "Recipe JSON copied and downloaded." / "LTCX saved." / "CSV saved.". Template header CSS block added to `f13ui-style`; the queue client's own buttons stay mounted but invisible. The Library "export" block keeps only the cell size slider (heading "export size"); the Builder block is empty (natives hidden). Help targets `export` / `bldexport` now point at `#w-recipe`.
- **Header message / alert():** the shared `F13UI.message` (note + action) already existed from stage 2; no `alert()` remains.
- **Test scripts** (scratchpad, `beam-s5-*`): not in the repo.

Stage 4 notes:
- **What changed:** quality buttons, `onQualityChange`, `currentQuality` and the `quality` help card are gone; `uSteps` / `uThresh` replace the old per-quality loop bound (`MARCH_MAX` 512, constant); the viewer draws interactive frames (160 steps) into an offscreen buffer at an adaptive 0.4-0.85 scale with a LINEAR blit, and one rest frame (384 steps, full res, DPR cap 2, was 1.5) in strips about 150 ms after the last change; `antialias:false`; the canvas buffer only resizes with the pane. `preserveDrawingBuffer` stays (the queue snapshot reads the canvas and a still frame is not redrawn).
- **On-demand loop:** every `raymarcher._dirty = true` (30 call sites, plus the view kit's redraw) is now a "something changed" kick via a property setter, so nothing else had to move. Overlay-only changes (Builder hover, armed point, snap density, symmetry, mode) call `raymarcher.overlay()` and redraw only the 2D overlay (axis gizmo, snap points, clip handle) instead of the ray-march; the armed pulse runs the overlay at 30 fps and stops under Reduce Motion. The beam uniforms (2 x 256 vec3) upload only when the beams change.
- **Stiffness surfaces:** `tick` became `draw`; they redraw on change, spin at most 30 fps while on screen (IntersectionObserver), pause while the viewer moves, stop under Reduce Motion, and rebuild on `webglcontextlost` / `restored`. The viewer rebuilds buffer, program, both render targets and the beams on restore.
- **Homogenization off the tick path:** `updateMetrics(cheapOnly)` / `Builder.updateMetrics(cheapOnly)`; the cheap readouts (beams, density, length) stay live, the solve is debounced 120 ms and flushed on `change` / pointer release. Deferred: radius and cell sliders, Builder radius, beam add / remove, undo / redo. Immediate: topology, tiling, material, clear, tab switch, import. Exports always compute fresh.
- **Bug caught by the pre-merge test:** kicking from inside the frame (auto-rotate) scheduled the next frame twice per frame, which grew exponentially and crashed the headless renderer; fixed (the loop schedules once). Worth checking in the other tools if they call a wake function from inside `frame`.
- **Test-harness notes:** swiftshader frames take 0.3-2.5 s here, so waits for rest frames are capped; `Builder.loadBeams` does not refresh the viewer (tests call `Builder.refresh()`), same as `main`.

## Decisions (Matt, 2026-11-25)

Shared, all wave 1 tools:
- **Quality:** automatic, as in TPMS. Remove the manual quality control (buttons or slider); its help (i) goes with it.
- **Stale analysis:** clear homogenization / stiffness results when the design changes, and on import. Exports carry results only for the current design.
- **Missing help cards:** add them; the (i) count rises by that number (record the new count).
- **Field sliders that re-bake:** show a low-res preview bake while dragging, full bake on release. Keep it only if it measures faster to first change than today and does not slow the full bake.
- **Accent:** derived from the tool colour in the F13LD brand guidelines v2.0 (hue kept, lifted to L 0.80 for the dark UI). Final value pending Matt.

This tool:
- **Accent (proposed):** olive-lime `oklch(0.80 0.15 121)` ≈ `#afcc54`, from brand stroke `#4A5A0F`. Close to the brand neon `#c8f542` used by TPMS; lower chroma if it reads the same.
- **Quality buttons:** removed (automatic). Pixel-ratio cap to 2 comes with the render-quality pattern.

- Library / Builder becomes a choice inside Cell. Recipe menu (Export JSON / Queue / Mesh / Lab) sends the Builder cell on Builder. LTCX and CSV in the Recipe menu. DPR cap 2. Ghost preview always on (checkbox removed). Cell size slider moves next to export. Import restores E_s / ν_s.
